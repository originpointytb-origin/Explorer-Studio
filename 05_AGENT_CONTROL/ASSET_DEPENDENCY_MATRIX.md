ASSET DEPENDENCY MATRIX (ADM)
PART I — DEPENDENCY GOVERNANCE
Chapter 1 — Purpose
Purpose
The Asset Dependency Matrix (ADM) documents every production relationship between approved 
assets within Explorer Studio.
While the Master Asset Registry records what assets exist, the Asset Dependency Matrix records 
how those assets depend upon one another.
Its purpose is to preserve production integrity by ensuring that changes to one asset can be 
evaluated against every related asset before implementation.
The Dependency Matrix therefore acts as the connective infrastructure linking the entire Master 
Asset Library into one coherent production ecosystem.
Objectives
The Asset Dependency Matrix exists to:
document asset relationships, 
•
prevent hidden production dependencies, 
•
support impact analysis, 
•
simplify maintenance, 
•
improve reuse, 
•
reduce production risk, 
•
support automation, 
•
preserve production knowledge. 
•
Guiding Principle
No asset exists in isolation.
Every approved asset participates in one or more production relationships.
Understanding those relationships is essential for sustainable long-term production.
   
   
Chapter 2 — Dependency Philosophy
Explorer Studio distinguishes between assets and relationships.
Assets create capability.
Relationships create production.
Therefore, relationships receive the same engineering discipline as assets themselves.
Dependency Rules
Every approved dependency shall be:
documented, 
•
traceable, 
•
reviewable, 
•
maintainable, 
•
version controlled. 
•
Undocumented dependencies are considered production defects.
